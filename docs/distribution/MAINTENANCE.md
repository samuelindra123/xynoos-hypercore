# Archive architecture and operations

Selected technology: Debian **apt-ftparchive**, with explicit signature/digest/version-ledger gates. Aptly offers snapshot/promotion management and reprepro offers package database/export management; both are mature choices. For this single-package, amd64 preview, apt-ftparchive avoids an opaque mutable database and lets reviewers inspect public Git history directly. Snapshot-like retention, version admission and safe promotion are implemented as explicit archive checks, not assumed properties of the index generator. [Debian reference](https://manpages.debian.org/trixie/apt-utils/apt-ftparchive.1.en.html).

The public append-only branch distribution/apt-history stores only apt/: pool/main/x/xynoos-hypercore .deb files, dists/preview/main/binary-amd64 Packages and Packages.gz, retained SHA256/SHA512 by-hash indexes, Release, InRelease, Release.gpg, a signed-indexed versions.json ledger and binary public key. Empty/unsigned/partial state cannot replace an existing archive. Release authenticates the ledger and indexes; indexes authenticate all .deb bytes. Duplicate versions, retrograde publication, wrong architecture, changed historical bytes, extra unindexed packages, invalid/expired state and missing signing identity fail closed. Explicit renewal admits no new packages through expired state.

Pool files and old by-hash indexes are never pruned automatically. Every historical version remains indexed/installable while this preview retention policy applies. Releases/tags/assets are never overwritten. Normal fast-forward Git push detects competing state changes; no force push is used. Both publish, recovery-promotion and renewal share one concurrency group. Studio/Pages calls share a separate global deployment group; every deployment assembles current website bytes plus latest verified history. A website-only update cannot silently erase /apt. No old website-only deployment path remains.

GitHub Pages publishes one artifact. Paths/animations/SEO/assets remain sourced from website/; repository metadata is copied under /apt. Before accepting deployment, HTTPS read-back checks website bytes and all historical package signatures/digests. Public HTTP failure is a failure, even after a successful deploy action. Acquisition uses by-hash to reduce index races; GitHub Pages/CDN cache propagation still exists, so maintainers must monitor failed reads and retry only boundedly. Clients never use insecure metadata fallback.

Release preparation reuses locked clean pinned Debian 13 sbuild/unshare roots, two builds and identical-byte reproducibility checks. .changes/.buildinfo checksum references remain intact; source archives are release assets. The CycloneDX SBOM covers locked Cargo registry dependencies and their licenses/checksums. It is not a complete OS/toolchain SBOM; buildinfo/bootstrap inventory records those build inputs. GitHub OIDC attestations cover every payload plus SHA256SUMS. Verification pins workflow, main source ref and exact commit before signing/publication. [GitHub attestation reference](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations).

Stable, other architectures, pruning and trust-anchor rotation require reviewed policy and separate acceptance. Monitor Pages limits/repository growth, 30-day metadata expiry, signing subkey expiry/revocation and GitHub scheduled-workflow inactivity. Weekly renewal may require owner environment approval. Do not weaken that approval to conceal missed maintenance. Recovery promotes exact existing attested release bytes; it never rebuilds an immutable published version.

# Phase 5 memory intelligence (experimental, read-only)

Run `cargo run --release -p xynoos-cli -- memory --interval-ms 1000` for JSON, or add `--human`. The command takes two sequential observations, then exits. Sampling is bounded to 100–60000 ms; it performs no kernel or application writes. JSON includes the observations, interval, diagnosis, advisory AURA decision, and schema version. Extract the `evidence` object and pass it to `memory --replay FILE` for deterministic offline reproduction. Replay is limited to 1 MiB; its interval and age are supplied by the evidence producer, not independently verified. Do not treat untrusted replay data as authenticated physical measurements. The full CLI is a development entry point; the existing distribution binary is unchanged.

PressureIQ reuses the existing meminfo, PSI, vmstat and diskstats parsers. It reads memory and I/O PSI, VM scan/steal, allocation stall and swap counters, memory and swap capacity, per-device disk sector counters, and ZRAM mm_stat, io_stat and block stat. Missing sources and counter resets produce null rates, never zero. Device counters are separately reported, not summed: partitions and stacked devices may overlap. Counters are pages or events per second, disk sectors are 512 bytes; ZRAM original/compressed and original/allocated ratios are null when their denominator is zero. Sequential reads are not atomic. Container-visible kernel data may represent the host, not the container's memory limit. ZRAM device disappearance and device counter reset invalidate the corresponding comparison. The sampling age is measured monotonically in the live command; evidence is not persistent monitoring.

The diagnosis returns overlapping classes. Direct reclaim means a direct-scan or allocstall counter increased. Swap activity means either swap counter increased; the experimental thrashing heuristic requires both directions >=10 pages/s and memory PSI some avg10 >=1% or full avg10 >=0.2%. Sustained means memory PSI some avg60 >=1% and current reclaim. Elevated means current PSI stalls plus reclaim or swap churn. I/O-amplified indicates concurrent memory stalls, reclaim and I/O PSI some avg10 >=5%; correlation does not prove that storage caused the stalls. ZRAM-heavy means original data on one device >=10% of RAM. Thresholds are initial heuristics, not calibrated diagnoses or evidence of a workload bottleneck. Low MemAvailable by itself never establishes starvation. A normal class requires the core fields and no threshold-level pressure. Missing core counters, reset, invalid interval or observations older than five seconds yield incomplete/unreliable. Other unavailable fields are listed as limitations. Rates do not measure reclaim event frequency: pgscan/pgsteal count pages, allocstall counts events. Short samples may miss intermittent behavior.

AURA deterministically recommends further observation or investigation, prioritizes incomplete evidence, and rejects physical mutation and unqualified buffer compression. Its cost statement describes bounded telemetry work, not a workload-specific CPU or benefit prediction. There is no automatic retry, cooldown timer, backoff state, or action execution in this advisory path; the operator controls resampling. This is intentionally not an optimizer.

## HyperMemory boundary

`PageStore` owns its buffers; it cannot compress Firefox or VS Code memory. Adaptive mode accounts retained buffer capacity and entry metadata against its configured budget and can keep incompressible pages raw. Compression, checksum, decompression, temporary buffers, allocator overhead and access latency cost CPU and memory; accounting is not a complete RSS bound. Recovery is limited to owned in-process data and integrity checks; process loss loses the store. Suitability depends on measured compressibility, retention time, access frequency and CPU budget. The new policy never invokes the store. A future cooperative integration requires explicit ownership, bounded allocation and temporary memory, workload-specific costs, failure recovery, cooldown and validated net benefit.

## Evidence and limitations

[Live example](reports/phase5/live-example.json), [human report](reports/phase5/human-example.txt), and [benchmark](reports/phase5/benchmark.txt) are from this workspace container, not the N5000. Five release runs took 101.84–102.32 ms including a 100 ms sleep and 1.50–1.74 ms child CPU each; cumulative child RSS high-water was 8704 KiB. This is a small smoke measurement, not an overhead guarantee. Reproduce with a release build and the command recorded in the benchmark.

PR #31's published body and review/comment records were inspected: the PR explicitly says physical preview.3 validation was pending. No physical preview.3 counter capture was available there. Its published lifecycle example is a Codespaces run, not physical N5000 evidence. Consequently N5000 reclaim/swap identification and heuristic accuracy on that machine remain unverified. Obtain timestamped consecutive raw procfs/sysfs samples with provenance, adapt them to the documented evidence schema, and replay before claiming that acceptance criterion. The existing synthetic tests are not physical evidence.

The workspace test suite originally failed `telemetry_errors_are_not_accepted` on the snapshot because this host lacked readable memory PSI and that earlier validation masked the injected meminfo error. The test now supplies valid PSI to isolate the intended failure; simulated transaction tests use explicit valid memory and PSI fixtures for the same reason. No control behavior was changed. Physical mutation, swap/ZRAM reconfiguration, process migration, cgroup/sysctl writes, service activation and daemon operation are not performed by this feature.
